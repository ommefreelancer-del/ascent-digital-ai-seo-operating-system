## Resolved: `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` are not a login mechanism

Confirmed by direct code read (`google-oauth.ts`, `google-search-console.ts`): these two variables authenticate **Google service connections** (Search Console, Business Profile, Sheets, Gmail, Drive), each with its own real, service-specific redirect URI under `/api/integrations/<service>/callback`. `web/src/server/auth.ts` registers only `CredentialsProvider` — there is no "Sign in with Google." `.env.example`'s comment documenting a NextAuth-style redirect URI for this variable is a stale/inaccurate comment in the repository itself (Engineering Follow-up — see `DOCUMENTATION_CONFLICTS.md`).

## Verifying a connection's live state

`web/src/server/backend/integration-health-check.ts` calls each integration's own real, already-used server functions directly (never through Boss Agent, a specialist agent, or LLM role-play). Statuses: `PASS` (real call succeeded), `FAIL` (real call attempted, real error), `NOT_TESTED` (not connected/configured, or no safe zero-argument call exists — Gmail), `PENDING` (Google Trends only, per its own documented blocked status — **NOT VERIFIED** what "blocked" specifically refers to). Every check is independently wrapped so one failure cannot take down the others; no credential/token value ever appears in a result's `detail` text.
