# Master Change Map

**The single most important reference in this documentation set.** Every row below was verified directly against the current repository (exact paths, function names, and behavior), not guessed. Where a claim could not be verified, it says so explicitly (`NOT VERIFIED IN CURRENT CODEBASE`) instead of describing a mechanism that may not exist.

Each row has all 11 required columns: **CHANGE/TASK**, **DOCS TO READ**, **EXACT CODE/CONFIG LOCATION**, **FILE PATH**, **WHAT IT CONTROLS**, **SAFE TO CHANGE**, **MUST NOT CHANGE CASUALLY**, **TESTING REQUIRED**, **DEPLOYMENT REQUIRED**, **DB MIGRATION REQUIRED**, **APPROVAL REQUIRED**. Rows are grouped by area for readability; the columns are identical across every group.

## Two codebases — read this before anything else

- **Root backend** (`Agents/`, `src/`, compiled to `dist/`) — the frozen Boss Agent routing engine and the root-layer specialist agent classes (`src/agents/<agent-id>/`). The web app only ever imports the **compiled** `dist/src/...` output (every `web/src/server/backend/*.ts` module that touches root code does `import(...)` against `../../../../dist/src`, never against `src/` directly).
- **Web app** (`web/`) — the Next.js product (UI, API routes, Prisma database, integrations). This is what actually runs and what real users interact with.

**A change to `src/` is invisible to the running web app until you rebuild.** Always run `npm run build` at the repo root after editing anything under `src/`, then restart the web app (`admin/DEPLOYMENT_OPERATIONS.md`).

## How to use this table

Find the row closest to what you want to change, open the exact file(s) listed, make the change, then follow the **TESTING REQUIRED** column before considering the change done, and check **APPROVAL REQUIRED** for whether the change touches an existing safety gate. If your change spans root backend (`src/`) code, remember the two-step build: `npm run build` at the repo root **first**, then rebuild/restart the web app — the web app never reads `src/` directly.

If a change scenario you need isn't listed here, it likely isn't implemented yet, or it's `NOT VERIFIED IN CURRENT CODEBASE` — check `technical/ARCHITECTURE.md` and `agents/INDEX.md` for the closest related, verified behavior before writing new code.
